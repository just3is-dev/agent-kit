# agent-kit

Плагин Claude Code для проектов, которые разрабатываются вместе с ИИ.
Одна фраза: спека это договор, команды двигают проект по договору,
хуки держат код зелёным.

## Принципы

1. Контракт `scripts/check | test | fix` — единственная связь плагина со
   стеком. Хуки и CI зовут только его.
2. Спека — источник истины. План и задачи живут внутри файла спеки.
   Разошлись спека и код — чинится код.
3. Хуки — короткая петля обратной связи, а не защита от агента.
4. Содержание в markdown, механика тонкая. Команда не длиннее 80 строк.
5. GitHub необязателен. Плагин работает в локальном репозитории.

Новый гейт добавляется только после реального дефекта на реальном
проекте, который он поймал бы.

## Установка

Из терминала (работает и для десктопного приложения, где диалога
`/plugin` нет):

```
claude plugin marketplace add just3is-dev/agent-kit
claude plugin install agent-kit@agent-kit
```

Локальный клон для разработки плагина: вместо `just3is-dev/agent-kit`
путь к папке. Либо декларативно, на уровне проекта —
`.claude/settings.local.json` (в git не коммитится):

```json
{
  "extraKnownMarketplaces": {
    "agent-kit": { "source": { "source": "github", "repo": "just3is-dev/agent-kit" } }
  },
  "enabledPlugins": { "agent-kit@agent-kit": true }
}
```

Команды вызываются с префиксом: `/agent-kit:init`, `/agent-kit:spec` и
т.д.; ниже для краткости без него.

## Цикл

```
идея → /spec → утверждение → /work (по задачам) → /verify → merge
```

## Команды

| Команда | Что делает |
|---|---|
| `/init [путь] [--local]` | Подключить проект: контракт `scripts/*`, CLAUDE.md, CI, git. `--local` — для чужого проекта, ничего не попадает в git |
| `/sync [путь]` | Сравнить скрипты контракта с шаблонами плагина и обновить выбранное |
| `/spec <идея>` | Идея → спека в `docs/specs/` с критериями приёмки и задачами; ветка `spec/NNN-slug` |
| `/spec NNN: <что изменить>` | Дельта к существующей спеке: номера критериев не сдвигаются, статус done → approved |
| `/work [NNN \| NNN.K]` | Задача из спеки: падающие тесты → код → зелёные проверки → коммит `[SPEC-NNN.K]` |
| `/verify [NNN]` | Сверка кода со спекой: по каждому критерию — тест, код, не найден, противоречит. Зелёная сверка → `done` и squash в main |

`/review` появится после обкатки на реальном проекте, см. [docs/plan.md](docs/plan.md).

## Спека

Один файл на фичу, frontmatter `status` (draft → approved → done) и
`covers` (пути, которые спека покрывает). Секции: Зачем, Что делаем,
Границы, Критерии приёмки (AC-N), Подход, Задачи (чеклист, одна строка
на задачу с её AC), Открытые вопросы. Задача одна — секции «Задачи» нет,
спека сама является задачей.

## Скиллы

`tdd` — критерий → падающий тест с именем `AC-N: ...` → минимальный код →
уборка. `adr` — когда и как писать `docs/adr/`.

## Шаблоны стеков

`node` (tsc + eslint/oxlint + vitest/jest по package.json), `astro`
(astro check + линтер, если есть; тест — сборка сайта + vitest, если
есть), `python`
(uv + ruff + mypy + pytest), `swift-ios` (swift format + SPM + smoke
xcodebuild), `monorepo` (корневой диспетчер по пакетам). Другой стек —
скрипты пишутся по образцу с маркером `# agent-kit/<стек>` в первой
строке комментария, по нему работает `/sync`.

## Контракт

Каждый проект имеет три скрипта: `scripts/check [файлы...]` (типы и
линт, с файлами — быстро), `scripts/test` (все тесты, пустой набор — не
провал), `scripts/fix [файлы...]` (автоформат, молча). Хуки и CI зовут
только их и не знают стека.

## Хуки

| Хук | Момент | Что делает |
|---|---|---|
| post-edit-check | после Edit/Write | `scripts/check <файл>`; ошибки возвращаются агенту |
| stop-test | агент завершает ход | `scripts/test`, если есть изменения; зелёный прогон кэшируется по диффу |
| guard | перед Bash | запрещает `--no-verify` и force push в main/master |
| prompt-timestamp, notification | ход и ожидание | локальные уведомления: «ждёт ответа», «задача завершена» после долгого хода |

Без `scripts/check` и `scripts/test` в проекте хуки молчат.

## Разработка кита

```
./scripts/check
./scripts/test
```

Коммиты в main, без обязательных PR. Спека на этап в `docs/specs/`.
