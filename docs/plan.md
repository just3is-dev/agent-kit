# План разработки agent-kit

Дата: 2026-10-13. Преемник agent-dev-kit, который разросся до 16 тысяч
строк гейтов вокруг самого себя. Этот план фиксирует, что берём, от чего
отказываемся и в каком порядке строим.

## Решения

- Спека — источник истины, всегда. При расхождении чинится код.
- Автономных многочасовых прогонов нет. Нет бюджетов, breaker'ов,
  журналов. `/work` всегда интерактивен.
- На своих проектах диффы не читаются: вместо них спека и отчёт
  `/verify`. На чужих — читаются, и там нужен PR-процесс, но плагин его
  не диктует.
- Только Claude Code. Содержание в markdown, механика тонкая, чтобы
  перенос на другой инструмент был возможен.
- Один разработчик, но всё состояние в репозитории, чтобы второй мог
  подключиться без переделки.

## Три сущности

- **Спека**: файл `docs/specs/NNN-slug.md` с frontmatter `status` и
  `covers`, секциями Зачем, Что делаем, Границы, Критерии приёмки
  (AC-N), Подход, Задачи (чеклист, одна строка на задачу с её AC).
- **Команды**: `/init`, `/spec`, `/work`, `/verify`, `/sync`,
  необязательная `/review`.
- **Хуки**: check после правки, test перед завершением, guard на
  `--no-verify` и force push, уведомления.

## Конвенции (идут в templates/base/CLAUDE.md)

- Ветка на спеку `spec/NNN-slug`, задачи — коммиты в ней, после зелёного
  `/verify` squash в main.
- Коммит: Conventional Commits с токеном `[SPEC-NNN.K]`. По токену
  команды находят дифф задачи без GitHub.
- Агент коммитит сам после каждой задачи, файлы добавляет явно.
- Правка спеки в том же коммите, что и код.
- Документы и коммиты на русском, код на английском. В чужом проекте
  побеждают его конвенции.
- `docs/backlog.md` — идеи и найденное по пути.
- Отчёт `/work`: сделано, критерии, в backlog, нужно решение.

## Что взято из agent-dev-kit

| Что | Изменения |
|---|---|
| post-edit-check, stop-test | как есть, без lib/paths.sh |
| notification, notify-send, prompt-timestamp | как есть |

| reviewer | необязательная команда /review, 4 пункта чеклиста |

## От чего отказались

ralph, autopilot, stats, журнал `.adk/`; bash-guard с парсером команд;
`adk.config.json` и политики; ac-check и AC-токены; гейты заголовков PR,
фронтматтера, бампа версии; `/plan`, `/consolidate`, decompose,
stack-choice; GitHub issues как обязательная часть; тесты на 11 тысяч
строк; ADR на каждый баг плагина.

## Этапы

| Этап | Содержание | Готово, когда |
|---|---|---|
| 0. Каркас (готов) | манифест, пять хуков, guard, смоук-тест | плагин ставится, хуки работают на проекте с контрактом |
| 1. Инициализация (готов) | шаблоны стеков, `/init` для пустого и существующего проекта, `--local` для чужих, `/sync` | любой проект получает контракт одной командой |
| 2. Спека и работа (готов) | шаблон спеки, `/spec` с дельтой, `/work` с задачами в спеке, tdd, adr, формат отчёта | полный цикл без GitHub |
| 3. Сверка (готов) | `/verify`, статусы спеки | спека источник истины на деле |
| 4. Обкатка (готов) | три обкатки: лендинг на Astro, четыре стека субагентами, чужой проект и `/sync` — итоги в [trials.md](trials.md) | список реальных проблем |
| 5. По итогам (готов) | 67 находок трёх обкаток закрыты в 0.1.2–0.1.4; `/review`, `/plan`, GitHub как опция, React Native — только если понадобятся на реальном проекте | только то, что показала обкатка |

Все этапы пройдены (2026-10-30). Дальше плагин развивается только по
находкам с реальных проектов.
