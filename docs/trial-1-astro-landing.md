# Обкатка 1: лендинг салона на Astro

Этап 4 плана. Проект с нуля: `/init` на пустой директории (стек astro),
SPEC-001 «лендинг салона на трёх языках», пять задач, `/verify`, squash в
main. Результат: 9 критериев, 24 теста, все критерии подтверждены тестами.

**Оговорка.** Плагин в сессии не был подключён, поэтому `/init`, `/work` и
`/verify` выполнялись вручную по тексту команд, а хуки (check после
правки, test перед завершением хода, guard) не работали. Обкатка
командного текста состоялась, обкатка хуков и самих слеш-команд — нет.

## Что сработало

- `/init` по маркерам и шаблонам: каркас, контракт `scripts/*`, CI,
  `CLAUDE.md`, backlog за один проход. `check` и `test` из шаблона astro
  прошли с первого раза.
- Спека с тремя вопросами вместо длинного интервью: хватило.
- Задача → тесты с `AC-N:` в имени → код → коммит `[SPEC-NNN.K]`: `/verify`
  нашёл все критерии grep'ом, без чтения кода.
- Правило «тест не ослабляется»: тест на размер шрифта поймал 13 px,
  чинился стиль, а не порог.

## Проблемы

1. **Критерий делится между задачами.** AC-2 («секции и якоря в шапке»)
   закрывался задачами 2 и 3. Тест пришлось писать на часть критерия и
   расширять позже. Нужно правило в `/spec` или в шаблоне: критерий
   целиком закрывается одной задачей, иначе задачи режутся иначе.
2. **tdd не учитывает сразу зелёные тесты.** Тест AC-7 (вёрстка при 360 px)
   прошёл на странице без стилей: он охраняет будущие стили, а не
   описывает отсутствующее поведение. «Сначала красный» тут невозможно.
   Помогла проверка мутацией (сломал CSS, тест покраснел). Это стоит
   записать в скилл `tdd`: сразу зелёный тест → докажи, что он ловит
   поломку.
3. **`/init` не знает про `@types/node`.** `check` упал, когда тесты стали
   читать `dist/` через `node:fs`. Шаг 5 `/init` для astro должен ставить
   `@types/node`, если проект использует vitest.
4. **Шаблон CI для astro без браузера.** Проект с Playwright требует шага
   `playwright install --with-deps chromium`; пришлось править `ci.yml`
   руками. Либо подсказка в шаблоне, либо `/sync` должен это понимать.
5. **`covers:` и файлы инфраструктуры.** `/verify` пункт 4 указал на
   `astro.config.mjs`, CI, `CLAUDE.md`, ADR, `package.json` как вне
   `covers:`. Это не нарушение границ, а шум. Нужно либо исключать
   известные файлы проекта из сверки, либо в шаблоне спеки подсказывать
   включать конфиги.
6. **Генератор Astro создаёт `AGENTS.md`**, `/init` про него молчит. Не
   конфликт (цель Claude Code, читается `CLAUDE.md`), но в `/init` нужно
   решить: оставить, сослаться из `CLAUDE.md` или удалить.
7. **Установка плагина в десктопном приложении.** `/plugin` — диалог
   терминала, из приложения его нет. В README нужна строка про это и про
   проектный `.claude/settings.local.json` с `extraKnownMarketplaces` и
   `enabledPlugins` (путь локальный, в git не коммитить).
8. **Тесты читают `dist/`, который может быть устаревшим.** `./scripts/test`
   всегда собирает заново, но ручная проверка `astro preview` после
   отката правок показала старую сборку. Не дефект плагина, но довод
   сделать `test` единственной точкой проверки.

## Не проверено

- Хуки: post-edit-check, stop-test (время `test` с Chromium на каждый ход!),
  guard.
- Слеш-команды как команды: поведение AskUserQuestion, ветка, формат
  отчёта `/work`.
- `/sync` и `--local`.
- Проект с БД, секция миграций из `CLAUDE.md`.
