# ADR — записи архитектурных решений

ADR читают вместо кода, чтобы понять «почему так». Файл
`docs/adr/NNN-<слаг>.md` по шаблону
`${CLAUDE_PLUGIN_ROOT}/templates/process/adr-template.md`, NNN —
максимальный номер плюс один.

## Когда писать

- Выбор между реальными альтернативами, где «почему» не восстановить из
  кода: библиотека, хранилище, протокол, паттерн.
- Отступление от дефолта проекта.
- Решение, которое дорого развернуть назад.

## Когда не писать

- Очевидный выбор без альтернатив.
- Пересказ того, что видно из кода.
- Решения уровня «как назвать переменную».

Сомневаешься — не пиши. Лишние ADR обесценивают нужные.

## Правила

- Одна страница: контекст → решение → последствия.
- Самодостаточно, без ссылок на историю чата.
- Задним числом не редактируется: решение изменилось — новый ADR со
  ссылкой «supersedes ADR-NNN», старому статус superseded.
